# History labels v1

`data/history/{world}/labels.jsonl` sits beside `index.jsonl` and records who named
each snapshot, one JSON object per line: `{"id": "<snapshot id>", "kind": "<kind>"}`.

The kind is kept out of the snapshot manifest on purpose. The manifest is hashed into
the snapshot id and is fail-closed for every older build (`contracts/backup/v2.md`), so
a field there would make the whole history unreadable for an older Quiltor or a second
device. The labels file is local only: it is not uploaded to a backup endpoint and does
not travel with cloud sync or project archives.

| kind | written by |
| --- | --- |
| `manual` | a name the author typed |
| `automatic` | an empty name when no chapter or profile changed |
| `changes` | an empty name when chapters or profiles changed |
| `before-restore` | the snapshot taken before a restore |
| `cloud-sync` | the snapshot taken when publishing a cloud sync |
| `before-cloud-sync` | the snapshot taken before pulling a cloud sync |
| `cloud-sync-conflict` | the snapshot that keeps the local side of a sync conflict |

Readers are lenient, because the file only words the display:

- a line that is not JSON, has an unknown kind, or names an id the index does not
  contain is ignored;
- a snapshot without a label is read by its stored name (the English names the server
  writes), and anything else is `manual`. This covers snapshots written before 3.25,
  snapshots restored from an endpoint, and an interruption between the index append
  and the label append.

Writers append the label right after the index entry, under the same lock.
