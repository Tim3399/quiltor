# SQLite migration contract v1

World databases carry `meta.schema_version`. Opening a database runs the
idempotent schema bootstrap and every missing forward step in one SQLite
transaction, then writes the current version. There is no automatic downgrade.

Published version numbers and their guarantees are immutable. A release that
changes the persisted shape appends one contiguous step and updates the golden
chain fixture. Restored snapshots are migrated before document reads or revision
bookkeeping. Document revisions are not advanced by schema-only migrations.

Schema v11 introduces the independent, non-canon Storyboard document. The
migration seeds one stable `main-storyboard` for worlds that do not yet have a
board and initializes `storyboards_revision` without touching manuscript or
story-world revisions.

Schema v12 adds `place_map_images`, the first table holding user-supplied
binary. Images are addressed by the SHA-256 of their bytes, so the same map used
twice occupies one row and a served image can be cached indefinitely. They live
inside the world database on purpose: the backup manifest admits `world.sqlite3`
and markdown mirrors and nothing else, so a sibling directory of image files
would be omitted from every snapshot and left stale by every restore. The step
adds no document revision and rewrites no existing row.

The fixture is intentionally declarative: Python verifies the live migration
constant and effects; other runtimes can decide whether they can open a database
without importing Python or parsing SQL source.
